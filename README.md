# ClaimsGenerator — претензии и иски по дебиторской задолженности

Программа берёт выгрузку «Отчёт по дебиторской задолженности» из 1С и по каждому
договору с просрочкой ≥ N дней (по умолчанию 5) сама формирует:

- **претензию** (.docx) — требование оплатить долг и пеню в течение 10 календарных дней;
- **исковое заявление** (.docx) — в экономический суд (прямой договор) или
  в арбитражную комиссию товарной биржи (биржевой договор).

Также программа считает пеню по ставке из договора и проценты по ст. 366 ГК РБ,
учитывает частичные оплаты, ведёт реестр «что отправлено — кому пора в суд»,
помечает долги с истёкшим сроком исковой давности и выгружает сводную таблицу.

Сделано для оптовой торговой компании (Республика Беларусь). Юрист раньше писал
претензии и иски вручную по образцам; программа повторяет их структуру и формулировки.

> **Все данные в репозитории вымышленные**: компания «Ромашка», покупатели «СтальТрейд»,
> «АвтоЗавод» и т.д., реквизиты (`BY00TEST…`, `УНП 100 000 001`), суммы и номера договоров.
> Реальные выгрузки, договоры и справочник покупателей в репозиторий не входят
> (см. `.gitignore`).

## Стек
Python 3.10+, стандартный `http.server` (локальный веб-интерфейс), pandas + xlrd/openpyxl
(чтение отчётов 1С), python-docx (генерация документов), Word через COM — по желанию
(чтение `.doc/.rtf` и подсчёт числа листов иска).

## Быстрый старт
```bash
pip install pandas xlrd openpyxl python-docx
python web.py                        # откроется интерфейс в браузере (127.0.0.1)

```

## Как работает расчёт

**Пеня.** Ставка определяется по типу договора: **0,1 % в день** — биржевой
(номер вида `01/XXXXX-XXX`), **0,5 % в день** — прямой. Ставку можно переопределить
для конкретного покупателя в `data/contragents.csv` (`Ставка_пени_%_override`).
Пеня считается **не более чем за 1095 дней** (общий срок исковой давности,
ст. 197 ГК РБ) — иначе по старым долгам она в разы превышает сам долг.

**Проценты по ст. 366 ГК РБ** считаются по каждой накладной по ставке
рефинансирования НБ РБ, действовавшей в каждом отрезке периода (если ставка
менялась, расчёт разбивается по датам). Формула — `сумма × ставка% / 360 × дни`.
История ставки — `data/refinancing_rate.csv`; кнопка «Обновить ставку НБ РБ»
скачивает её с открытого API Нацбанка (`api.nbrb.by/refinancingrate`),
плюс тихая проверка раз в сутки при запуске. Отключается одной строкой —
`CHARGE_INTEREST_366 = False` в `company.py`.

**Госпошлина / арбитражный сбор** — ставки в `data/tariffs.json`. Пока там
`"проверено": false`, сумма в текст иска не подставляется (чтобы в суд не ушла
непроверенная цифра), а в сводной таблице показывается как ориентировочная.

**Частичные оплаты.** В отчёте 1С виден только остаток долга, поэтому платежи
вносятся в окне и хранятся в `data/payments.csv`. Каждая погашенная часть «живёт»
до своей даты оплаты, день оплаты в просрочку не входит:

```
долг по ТТН 10 000,00, просрочка с 28.01, ставка 0,1 % в день
06.02 п/п №101 оплачено 3 000,00  ->  28.01–05.02 =  9 дн. ->  27,00
09.02 п/п №102 оплачено 2 000,00  ->  28.01–08.02 = 12 дн. ->  24,00
остаток         5 000,00          ->  28.01–18.02 = 22 дн. -> 110,00
                                                   итого:     161,00
```

## Окно программы

`Претензии.bat` (или `python web.py`) поднимает локальный сервер на 127.0.0.1
и открывает интерфейс в браузере. Наружу ничего не уходит.

1. **Отчёт** — выбрать выгрузку 1С, задать порог просрочки и дату расчёта.
2. **«Показать должников»** — таблица: покупатель, договор, тип, дни просрочки,
   сумма, статус претензии, предупреждения (нет реквизитов, срок давности > 3 лет,
   мелкая сумма). Поиск, сортировка, быстрые фильтры.
3. **«Сделать претензии» / «Сделать иски»** по отмеченным строкам — с предупреждением
   о рискованных делах. В конце — список файлов с суммами.
4. **Реквизиты покупателей из договора** — загрузить договор (.docx/.doc/.rtf/.pdf
   с текстовым слоем), программа сама отделит сторону покупателя от своих реквизитов
   и вытащит наименование, УНП, адрес, счёт, банк, подписанта; после проверки
   данные пишутся в справочник, заполненное вручную не затирается.
5. **Частичные оплаты** и **реестр отправки**: «сформирована → отправлена →
   ждём ответа → срок истёк, можно в суд / оплачено / оплачено частично».

## Командная строка

```bash
python main.py list      --report examples/Отчет_пример.xlsx
python main.py pretenzii --report examples/Отчет_пример.xlsx --min-days 5
python main.py iski      --report examples/Отчет_пример.xlsx --ready-for-suit
python main.py pretenzii --report examples/Отчет_пример.xlsx --contragent "СтальТрейд" --contract "020126/2"
python main.py mark-sent --report examples/Отчет_пример.xlsx --contragent "СтальТрейд" --sent-date 20.07.2026
python main.py update-rate
```

Готовые документы раскладываются по покупателям:
```
output/
  СтальТрейд/pretenzii/...docx
  СтальТрейд/iski/...docx
  _summary_pretenzii.csv
  _summary_iski.csv
```

## Структура проекта

```
├── Претензии.bat                 # запуск двойным щелчком (Windows)
├── web.py                        # локальный сервер интерфейса
├── templates/index.html          # интерфейс (HTML/CSS/JS)
├── main.py                       # командная строка
├── parser.py                     # разбор выгрузки 1С (xls/xlsx/csv)
├── docgen.py                     # генерация .docx претензии и иска
├── rates.py                      # ставка рефинансирования, проценты ст. 366, госпошлина
├── payments.py                   # частичные оплаты по накладным
├── journal.py                    # реестр отправленного
├── contracts.py                  # разбор договора, извлечение реквизитов
├── company.py                    # реквизиты истца (демо), ставки пени, куда подавать спор
├── build_contragents_template.py # создание/дополнение data/contragents.csv
├── examples/Отчет_пример.xlsx    # демо-выгрузка 1С на вымышленных данных
├── tests/
│   ├── control_set.py            # 7 договоров с заранее посчитанными ответами
│   ├── web_api.py                # все кнопки окна (нужен отчёт)
│   └── audit_data.py             # что в рабочих файлах настоящее, а что от тестов
└── data/
    ├── refinancing_rate.csv      # история ставки рефинансирования НБ РБ
    └── tariffs.json              # базовая величина, госпошлина, арбитражный сбор
```

Рабочие файлы (`data/contragents.csv`, `data/journal.csv`, `data/payments.csv`,
`data/contracts/`, `output/`) создаются при работе и в репозиторий не попадают.

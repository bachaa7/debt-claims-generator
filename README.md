# Debt Claims Generator

**Программа, которая из выгрузки дебиторской задолженности 1С сама готовит претензии и исковые заявления по каждому просроченному договору: с расчётом пени, процентов и частичных оплат.**

Python · pandas · python-docx · http.server · API Нацбанка РБ · Word COM (опционально)

---

## Задача

У оптовой компании десятки покупателей с просроченными платежами, у части из них —
по нескольку договоров и накладных. Юрист готовил претензии и иски вручную:

- искал в отчёте 1С просроченные договоры;
- для каждой накладной считал пеню по ставке из договора;
- считал проценты по ст. 366 ГК РБ по ставке рефинансирования, которая за период
  могла меняться несколько раз;
- учитывал частичные оплаты (каждая погашенная часть считается до своей даты);
- вписывал реквизиты покупателя из договора и собирал документ по образцу.

Ошибка в расчёте — это проигранная часть требований в суде.

## Решение

Локальная программа с веб-интерфейсом в браузере (данные никуда не уходят — сервер
работает на `127.0.0.1`):

1. **Разбор отчёта 1С** «Дебиторская задолженность» (`.xls/.xlsx/.csv`): контрагент,
   договор, накладные, сроки, остатки. Учтены особенности выгрузки — старый `.xls`
   без кодировки, разные написания «Договор №/N», ячейки с переносами строк.
2. **Тип договора определяется по номеру**: биржевой (через товарную биржу) или прямой.
   От него зависят ставка пени, пункты договора в тексте, куда подавать иск
   (арбитражная комиссия биржи или экономический суд) и состав приложений.
3. **Расчёт по каждой накладной**:
   - пеня по ставке договора, не более чем за 1095 дней (срок исковой давности);
   - проценты по ст. 366 ГК РБ — период разбивается по датам изменения ставки
     рефинансирования; история ставки обновляется с API Нацбанка
     (`api.nbrb.by`) кнопкой и автоматически раз в сутки;
   - частичные оплаты: каждая погашенная часть считается до своей даты оплаты;
   - госпошлина / арбитражный сбор по ставкам из `tariffs.json`
     (не печатается в иске, пока ставки не отмечены как проверенные).
4. **Генерация `.docx`** претензий и исков по структуре и формулировкам реальных образцов
   юриста; при наличии Word считается настоящее число листов иска для приложений.
5. **Реквизиты покупателя из договора**: загрузить договор (`.docx/.doc/.rtf/.pdf`),
   программа отделяет сторону покупателя от реквизитов истца и вытаскивает
   наименование, УНП, адрес, счёт (в т.ч. с кириллическими «двойниками» латинских букв),
   банк, подписанта.
6. **Реестр**: претензия сформирована → отправлена → ждём ответа → срок истёк,
   можно в суд / оплачено / оплачено частично. Фильтр «Готовы к иску».
7. **Предупреждения о рисках**: нет реквизитов, срок давности больше 3 лет,
   долг меньше порога, при котором иск экономически невыгоден.

## Что сделал я

- Разобрал реальные иски юриста и договоры, вывел правила расчёта и проверил программу
  на них: результат совпал с исками юриста до копейки (включая случай с частичной оплатой).
- Написал разбор выгрузки 1С, расчёт пени и процентов с разбивкой по ставкам,
  учёт частичных оплат и госпошлины.
- Сделал генерацию документов на python-docx по образцам юриста.
- Написал извлечение реквизитов из договоров разных форматов.
- Сделал локальный веб-интерфейс без внешних зависимостей (`http.server` + HTML/JS):
  таблица должников с поиском, сортировкой и фильтрами, реестр, частичные оплаты.
- Покрыл расчёт контрольным набором: 7 договоров с заранее посчитанными ответами
  (`tests/control_set.py`) и проверка всех кнопок интерфейса (`tests/web_api.py`).

## Пример расчёта частичной оплаты

```
долг по ТТН 10 000,00, просрочка с 28.01, ставка 0,1 % в день
06.02 п/п №101 оплачено 3 000,00  ->  28.01–05.02 =  9 дн. ->  27,00
09.02 п/п №102 оплачено 2 000,00  ->  28.01–08.02 = 12 дн. ->  24,00
остаток         5 000,00          ->  28.01–18.02 = 22 дн. -> 110,00
                                                   итого:     161,00
```

## Запуск

```bash
pip install -r requirements.txt
python web.py                                   # интерфейс в браузере
python tests/control_set.py                     # контрольный расчёт
python tests/web_api.py examples/Отчет_пример.xlsx
```

В интерфейсе выберите демо-отчёт `examples/Отчет_пример.xlsx` → «Показать должников» →
отметьте договоры → «Сделать претензии» или «Сделать иски».

На Windows можно запускать двойным щелчком по `Претензии.bat`.

### Командная строка

```bash
python main.py list      --report examples/Отчет_пример.xlsx
python main.py pretenzii --report examples/Отчет_пример.xlsx --min-days 5
python main.py iski      --report examples/Отчет_пример.xlsx --ready-for-suit
python main.py pretenzii --report examples/Отчет_пример.xlsx --contragent "СтальТрейд" --contract "020126/2"
python main.py mark-sent --report examples/Отчет_пример.xlsx --contragent "СтальТрейд" --sent-date 20.07.2026
python main.py update-rate
```

Документы раскладываются по покупателям: `output/<Покупатель>/pretenzii/` и `.../iski/`,
плюс сводные таблицы `output/_summary_*.csv`.

## Структура

```
web.py                         локальный сервер интерфейса
templates/index.html           интерфейс (HTML/CSS/JS)
main.py                        командная строка, отбор договоров
parser.py                      разбор выгрузки 1С
docgen.py                      генерация претензий и исков (.docx)
rates.py                       ставка рефинансирования, проценты ст. 366, госпошлина
payments.py                    частичные оплаты
journal.py                     реестр отправки
contracts.py                   извлечение реквизитов из договоров
company.py                     реквизиты истца (демо), ставки пени, суды, приложения
build_contragents_template.py  создание/дополнение справочника покупателей
data/refinancing_rate.csv      история ставки рефинансирования НБ РБ
data/tariffs.json              базовая величина, госпошлина, арбитражный сбор
examples/Отчет_пример.xlsx     демо-выгрузка 1С
tests/                         контрольный расчёт и проверка интерфейса
```

Рабочие файлы (`data/contragents.csv`, `data/journal.csv`, `data/payments.csv`,
`data/contracts/`, `output/`) создаются при работе и в репозиторий не попадают.

## Правовая основа

Ст. 197, 290, 311, 314, 366, 456, 486 Гражданского кодекса Республики Беларусь.
Тексты шаблонов перед реальным применением нужно согласовать с юристом.

## Данные

Все данные в репозитории **вымышленные**: истец «Ромашка», покупатели «СтальТрейд»,
«АвтоЗавод» и др., реквизиты (`BY00TEST…`, `УНП 100 000 001`), суммы и номера договоров.
Реальные выгрузки, договоры и справочник покупателей в репозиторий не входят.
